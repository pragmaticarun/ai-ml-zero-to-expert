Block 1: Concept lesson (1h15)

Base vs instruct models. A base model continues text. Ask it a question and it may continue with more questions, as Day 99's greedy loop showed. An instruct (chat) model has been further trained to answer. Instruction tuning is the first step of that post-training.

Supervised fine-tuning (SFT). Collect (instruction, response) pairs and fine-tune with the next-token loss on the formatted conversation. Wei et al. (2022), "Finetuned Language Models Are Zero-Shot Learners" (FLAN), and Ouyang et al. (2022), "Training language models to follow instructions with human feedback" (InstructGPT), established the recipe: SFT on demonstrations, then preference optimisation (Day 106).

Chat templates. Conversations are serialised with special tokens. SmolLM2-Instruct uses the ChatML style: <|im_start|>system … <|im_end|>, <|im_start|>user … <|im_end|>, <|im_start|>assistant. The template lives in the tokenizer (tokenizer.apply_chat_template). Use the exact template the model was trained with; a mismatch silently degrades quality. add_generation_prompt=True appends the assistant header so the model starts answering.

Prompt-loss masking. Usually only the response tokens are trained: set the labels of system and user tokens to −100. Arguments for it: the model should learn to answer, not to generate user questions; and long prompts would otherwise dominate the loss. Arguments against: for short prompts it may matter little, and some work finds that training on prompts also helps. We test it.

Stop tokens. The response must end with <|im_end|> in training, and generation must stop on that token. Our first run forgot to pass it as an EOS token to generate: the model produced the right words and then rambled ("window tiger coffeeaidaidaid"), scoring 0.07. A one-line fix (eos_token_id=[…, im_end]) is the difference between a broken and a working evaluation.

Our task. Reversing the order of 3-5 words from a 40-word list ("Reverse the order of these words: red fish blue" → "blue fish red"). It is synthetic, automatically checkable, and something a 135M base model cannot do zero-shot.

Block 2: Worked example (45 min)

Run code/week-15/day103_instruction_tuning.py (about 6 minutes). 2,000 training examples; 40 held-out prompts not in the training set; LoRA r = 16 on all linear layers, lr 1e-3, 250 steps of 8 examples. Verified: - The rendered template contains a default system prompt ("You are a helpful AI assistant named SmolLM, trained by Hugging Face"), then the user turn, then <|im_start|>assistant. - One example is 48 tokens, of which only 6 (the answer plus <|im_end|>) count in the masked loss. - Zero-shot exact match on the 40 held-out prompts: base 0.00, SmolLM2-135M-Instruct 0.00. - After SFT with prompt masking: exact match 1.00 (135 s). Sample: "coffee tiger window" → "window tiger coffee". - After SFT without masking: also 1.00 (132 s).

So on this task the masking choice made no difference: the prompt is highly regular, and 250 steps were enough either way. Report it as a null result for this setting, not as evidence that masking never matters. Harder tasks with varied, long prompts are where masking is usually argued to matter.

Block 4: Practice problems (1h)

  1. What fraction of tokens is trained with masking in our example? Answer: 6/48 = 12.5%.
  2. Why did the instruct model score 0 zero-shot? Answer: a 135M model cannot reliably follow this instruction; it was never trained on it.
  3. What is the effect of forgetting the stop token in evaluation? Answer: correct answers followed by junk fail exact match.
  4. Why use a synthetic task? Answer: unlimited data, exact automatic grading, no licence issues.

Extra notes: real SFT data

Public instruction datasets range from human-written (such as Databricks' Dolly) to model-generated (such as Alpaca-style data), and modern recipes mix many sources with filtering. Quality and diversity matter more than size: Zhou et al. (2023), "LIMA: Less Is More for Alignment", report strong results from about 1,000 carefully curated examples. Always check the licence, because some datasets generated with commercial models forbid certain uses.

Going deeper (optional)

Read the chat-templating page of the Hugging Face transformers documentation.

Interview-style question (15 min, written)

"Your fine-tuned chat model keeps generating the user's next turn after its answer. Why?" Missing <|im_end|> in training targets, or the stop token not set at inference, or a template mismatch.

Common mistakes / how to debug

  • Training on one template and serving another.
  • Masking the end-of-turn token, so the model never learns to stop.
  • Test prompts that also occur in the training set (we filter them out).
