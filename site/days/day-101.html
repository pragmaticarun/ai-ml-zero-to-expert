Block 1: Concept lesson (1h15)

Low-rank adaptation (Hu et al., 2021, "LoRA: Low-Rank Adaptation of Large Language Models"). Freeze the pretrained weight W (d_out × d_in). Learn an update ΔW = B·A with A of shape r × d_in and B of shape d_out × r, with rank r much smaller than d. The layer computes

y = W x + (α / r) · B A x.

  • Initialisation: A random, B zero, so ΔW = 0 and training starts exactly at the pretrained model.
  • Scale α / r: keeps the update size comparable across ranks, so you can change r without retuning the learning rate much.
  • Parameters: r·(d_in + d_out) per adapted matrix instead of d_in·d_out.
  • Merging: after training, W' = W + (α/r)·B A gives a plain model with zero inference overhead. Or keep adapters separate and swap them per task on one shared base.

Why it works. Hu et al. report that the weight updates needed for adaptation have low "intrinsic rank": a small r captures most of the benefit for many tasks. It is not guaranteed for every task; tasks that need much new knowledge benefit from higher r or full fine-tuning.

Memory benefit. Gradients and Adam states are needed only for A and B. The frozen W can even be stored in lower precision (Day 102). The forward and backward activations are still needed, so LoRA saves optimiser memory more than activation memory.

PEFT. The peft library wraps a model: get_peft_model(model, LoraConfig(r, lora_alpha, target_modules, lora_dropout)), and offers merge_and_unload(), saving adapters only, and many other methods (prefix tuning, IA³ and others).

Block 2: Worked example (45 min)

Run code/week-15/day101_lora.py (119 s). LoRA r = 8, α = 16 on q_proj and v_proj in all 30 layers, lr 1e-3, 100 steps of 4 × 128 tokens. Verified: - Trainable 460,800 of 134,975,808 (0.34%). Check: per layer, q (576→576) adds 8·(576+576) = 9,216 and v (576→192) adds 8·(576+192) = 6,144, so 15,360 × 30 = 460,800. - Logits change at init (B = 0): 0.0e+00. The adapted model is exactly the base model before training. - My LoRA: 0.47 s/step (vs 0.88 for full fine-tuning), validation perplexity 26.29 → 23.19. - Merging into W: max logit difference 7.4e-05 (float32 rounding), and the parameter count returns to 134,515,008. - peft with the same config: trainable 460,800, equal to mine (True); after 100 steps with the same seed, validation perplexity 23.16 (mine 23.19). merge_and_unload() returns a plain LlamaForCausalLM. - Compare Day 100: full fine-tuning reached 21.38 with the same steps. LoRA on q,v recovered about 60% of that improvement ((26.29 − 23.19)/(26.29 − 21.38) ≈ 0.63) with 0.34% of the trainable parameters. Day 105 tests more ranks and targets.

Block 4: Practice problems (1h)

  1. LoRA parameters for one 4096 × 4096 matrix at r = 16? Answer: 16·8192 = 131,072 (vs 16.8M).
  2. Why is B initialised to zero rather than A? Answer: either makes ΔW = 0, but with both zero no gradients flow; zero B + random A gives a nonzero gradient for B.
  3. What does merging cost at inference? Answer: nothing extra; the matrix shape is unchanged.
  4. Why is the merge diff 7.4e-05, not 0? Answer: float32 rounding: x·(W + ΔW) is not bitwise equal to xW + xΔW.
  5. When is serving unmerged adapters useful? Answer: many tasks sharing one base model; hot-swapping adapters per request.

Extra notes: where to put adapters

The original paper adapted attention matrices. Later practice (for example in QLoRA, Day 102) adapts all linear layers including the MLP, which often helps more than raising r on attention alone. Day 105 tests exactly this trade-off at CPU scale.

Going deeper (optional)

Read Hu et al. (2021), section 4 (method) and section 7 (rank analysis).

Interview-style question (15 min, written)

"Explain LoRA to a colleague and when you would not use it." Frozen W plus a trainable low-rank update; cheap, swappable, mergeable. Avoid when the task needs large new knowledge or when you can afford full fine-tuning and want the last bit of quality.

Common mistakes / how to debug

  • Forgetting to freeze the base: all parameters train and memory explodes.
  • Wrong scale (α instead of α/r) when comparing with peft.
  • Optimiser built over all parameters including frozen ones (harmless but wasteful); build it over requires_grad only.
