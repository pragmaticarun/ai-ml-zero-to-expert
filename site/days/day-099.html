Block 1: Concept lesson (1h15)

The Hub. The Hugging Face Hub hosts model repositories: a config.json (architecture), weights (model.safetensors), tokenizer files, and a model card (license, training data, intended use, limitations). Always read the card and the license before use.

The three objects. - AutoTokenizer.from_pretrained(name): text ↔ token ids, plus special tokens and the chat template. - AutoModelForCausalLM.from_pretrained(name): picks the right class from config.json (SmolLM2 is a Llama-architecture model, so you get LlamaForCausalLM). - model.generate(...): the decoding loop (greedy, sampling, beam search), with the KV cache handled for you. from_pretrained downloads into the cache (HF_HOME) once; later loads are local. Setting HF_HUB_OFFLINE=1 guarantees no network access, which makes runs reproducible.

What is inside SmolLM2-135M. It is the Week 14 GPT grown up: pre-norm blocks (RMSNorm), RoPE positions (Day 93), SwiGLU MLPs, tied embeddings, and grouped-query attention (GQA): 9 query heads share 3 key/value heads, which shrinks the KV cache 3× (Day 111).

Forward pass and loss. model(input_ids=x, labels=x) returns .loss, the mean next-token cross-entropy. The library shifts labels internally, so you pass the same tensor as input and labels. Positions with label −100 are ignored (Day 103 uses this to mask prompts).

datasets. The datasets library loads Hub datasets as memory-mapped Arrow tables with .map, .filter and streaming. This week our data is small and local, so we tokenise plain tensors; the concepts transfer.

Block 2: Worked example (45 min)

Run code/week-15/day99_hf_basics.py (9 s with a warm cache). Verified: - 134,515,008 parameters; 30 layers, d_model 576, 9 heads, 3 KV heads, vocabulary 49,152, max positions 8,192, rope_theta 100,000; tied embeddings True; BOS and EOS are both <|endoftext|>. - "The quick brown fox jumps over the lazy dog." → 10 tokens: The, Ġquick, Ġbrown, … (Ġ marks a leading space in byte-level BPE). - Next-token distribution after "The capital of France is": ' the' 0.262, ' Paris' 0.094, ' located' 0.073, ' called' 0.044, ' a' 0.039. The correct fact is in the top 2, but not the top 1. - Greedy decoding of 30 tokens (0.38 s) loops: "the capital of the country. The capital of France is the capital of the …". Sampling (temperature 0.8, top-k 50, seed 0) gives "the city of Paris, and the name derives from the Latin word for city …", fluent but with an invented etymology. A 135M model is fluent before it is reliable. - Shakespeare validation perplexity (16 windows of 256): 24.42 (3.196 nats/token). Our Week 14 BPE model scored 3.470 nats/token, but on a different tokenizer, so compare in bits per character, not per token (practice problem 3).

Block 4: Practice problems (1h)

  1. Why do k_proj/v_proj have 192 outputs? Answer: 3 KV heads × 64 dims per head (576/9 = 64).
  2. Why pass labels=input_ids without shifting? Answer: the model shifts internally.
  3. Convert 3.196 nats/token to bpc given ~3.10 characters per SmolLM token (Day 96). Answer: 3.196 / 0.693 / 3.10 ≈ 1.49 bpc, far better than our 2.19.
  4. Why did greedy decoding loop? Answer: once a phrase is likely, repeating it stays likely; greedy has no randomness to escape.

Extra notes: precision and memory

At fp32, 134.5M parameters take 538 MB; bf16 halves that. Inference needs the weights plus the KV cache; training needs far more (Day 100). On CPU, fp32 is the safe default; bf16 on CPU works in recent PyTorch but is not always faster.

"What happens when you call AutoModelForCausalLM.from_pretrained?" Resolve the repo, download or read cached config and weights, instantiate the class named in the config, load the safetensors weights, tie embeddings if configured.

Common mistakes / how to debug

  • Mixing a tokenizer from one model with weights from another.
  • Forgetting model.eval() / torch.no_grad() for inference.
  • Reading a perplexity without checking context length and window count.
