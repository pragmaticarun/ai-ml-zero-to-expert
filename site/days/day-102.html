Block 1: Concept lesson (1h15)

Choosing a LoRA configuration. Three knobs: rank r, scale α, and target modules. For a Llama-style block the linear layers are q, k, v, o (attention) and gate, up, down (SwiGLU MLP). Adapting more modules adds parameters roughly linearly; raising r does too.

QLoRA (Dettmers et al., 2023, "QLoRA: Efficient Finetuning of Quantized LLMs"). Key ideas: 1. Store the frozen base in 4-bit (their NF4 data type, designed for normally distributed weights), with double quantisation of the scale factors. 2. Dequantise blocks on the fly to bf16 for each matmul. 3. Train LoRA adapters (in bf16) on all linear layers. 4. Use paged optimisers to survive memory spikes. The paper reports fine-tuning a 65B model on a single 48 GB GPU while matching 16-bit fine-tuning quality on their benchmarks.

Why it works. Gradients flow through the quantised weights to the adapters, but the quantised weights are never updated. The adapters can partly compensate for quantisation error, because they are trained with the quantised base in the loop.

Group-wise quantisation in one paragraph (Day 110 goes deeper). Split a weight matrix into groups of g values. For each group store a scale s = max|w| / 7 and integers q = round(w / s) clipped to [−8, 7] (4 bits). Dequantise as q·s. Memory: half a byte per weight plus a 16-bit scale per group (for g = 64, 0.53 bytes per weight vs 4 for fp32).

CPU honesty. The bitsandbytes 4-bit kernels used by QLoRA in practice target GPUs. Here we simulate 4-bit: we replace each frozen weight with its quantise-dequantise round trip (the same numerical error, but stored in fp32, so no memory is saved on this box). This shows the quality effects, not the memory savings.

Simulated 4-bit (absmax, group 64) on the 7 linear layers of every block: - 106,168,320 weights quantised (78.9% of parameters; the embedding table stays fp32). - Their memory: fp32 405 MiB, bf16 202 MiB, int4 with an fp16 scale per 64 54 MiB. - Validation perplexity: fp32 base 26.29, 4-bit base 36.89. Naive round-to-nearest 4-bit hurts a small model noticeably (larger models usually tolerate it better, and better methods such as NF4, GPTQ and AWQ lose less; Day 110). - QLoRA-style: LoRA r = 8 on all linear layers (2,442,240 trainable) over the frozen 4-bit base, 60 steps (33 s): perplexity 25.46. That is better than the unquantised base (26.29). The adapters both undid the quantisation damage and adapted to Shakespeare. We did not run the fp32 + LoRA comparison at 60 steps here, so we cannot say how much quality the 4-bit base cost after training; that is lab exercise 1.

Block 4: Practice problems (1h)

  1. Memory of a 7B base at 4-bit with fp16 scales per 64? Answer: 7e9 × (0.5 + 2/64) bytes ≈ 3.7 GB.
  2. Why can't we update the 4-bit weights directly? Answer: they are discrete; tiny gradient steps round away. Adapters stay in high precision.
  3. Why does adapting all linear layers cost 2.65× the parameters of q,k,v,o at the same r? Answer: the MLP matrices are larger (576 ↔ 1,536).
  4. Why might the quantised model + LoRA beat the fp32 base? Answer: the adapters were trained on the target domain; the base was not.

Extra notes: other PEFT methods

Prefix/prompt tuning learns virtual tokens prepended to every layer's keys and values; IA³ learns per-channel scaling vectors; adapters (Houlsby et al., 2019) insert small bottleneck MLPs. LoRA dominates in practice because it merges away at inference and is simple to apply.

Going deeper (optional)

Read Dettmers et al. (2023), section 3, on NF4 and double quantisation.

Interview-style question (15 min, written)

"You need to fine-tune a 13B model on one 24 GB GPU. Plan it." 4-bit base (~7 GB), LoRA on all linear layers, bf16 compute, gradient checkpointing, small micro-batch with gradient accumulation, paged optimiser.

Common mistakes / how to debug

  • Target-module names that match nothing: peft errors out or you train zero parameters; always print trainable parameters.
  • Quantising the embedding/head (often kept in higher precision).
  • Expecting memory savings from a simulated quantisation.
