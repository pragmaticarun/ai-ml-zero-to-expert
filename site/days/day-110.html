Block 1: Concept lesson (1h15)

An evaluation number is a measurement with error bars and assumptions. Six pitfalls cause most bad conclusions.

1. Small samples. With n test items and accuracy p, the standard error is about √(p(1−p)/n). On 40 items at p = 0.2 that is about 0.06, so differences of 0.03-0.06 are noise. Report a confidence interval; the bootstrap (resample the per-item results with replacement many times) is simple and assumption-light.

2. Prompt sensitivity. Small models, and sometimes large ones, change their answers when the instruction is reworded, the casing changes or punctuation is removed. One prompt template is one sample from a distribution of reasonable prompts. Report several, or fix the template and say so.

3. Metric choice. Exact match, normalised match (lowercase, strip punctuation) and "contains the answer" can give different numbers for the same outputs. "Contains" can reward a model that outputs many candidates. Choose the metric before looking at results and report how it was computed.

4. Contamination. If test items (or close variants) appear in training data, scores measure memorisation. Check exact overlap and n-gram overlap. For public benchmarks and web-trained models you usually cannot fully check, which is why fresh, private or dynamically generated tests matter.

5. Judge bias. LLM judges have position, length and self-preference biases. Week 15 measured this: the 135M instruct judge gave 0 of 16 consistent verdicts when the two answers were swapped.

6. Optimising the metric. Once a number is a target, models and people tune toward it (Goodhart's law). The Day 107 RM shortcut and the Day 111 reward exploitation are versions of this.

Block 4: Practice (1h)

  1. Model A scores 0.23 and model B 0.20 on the same 40 items. What can you conclude?
  2. Why is a paired comparison more powerful than comparing two separate CIs?
  3. Give an example where "contains" overstates performance.
  4. Why might a model trained on one prompt template drop on a paraphrase?

Answers. (1) Nothing reliable: the difference is about one item, and Day 110's CI for one model spans [0.07, 0.30]. (2) Item difficulty is shared, so variance from "which items happened to be chosen" cancels. (3) A model that outputs both orders, or a list of guesses, contains the answer without giving it. (4) Fine-tuning on a narrow template teaches template-specific behaviour (measured: 0.17 → 0.07 with lowercase and no colon).

Extra notes

The bootstrap CI covers sampling of items only. It says nothing about prompt choice, decoding settings, random seeds of training, or whether the test measures what you care about. Training-seed variance is its own source of noise: retrain with two seeds before trusting a small gain. Week 15's multiple-choice set gave every model the same score (0.88), which is the opposite pitfall: a test that cannot separate models.

Going deeper

  • Read the "Holistic Evaluation of Language Models" (HELM) paper's discussion of prompt and metric choices.
  • Search for papers on benchmark contamination detection and note which methods need access to training data.
  • Read about Chatbot Arena's pairwise human-preference evaluation and its own biases.

Interview-style question (15 min)

"A new model beats the old one by 2 points on a public benchmark. What do you need before shipping?" Points: size of benchmark and CI or paired test, multiple prompts and seeds, contamination check, task-relevant private evals, failure analysis, safety checks, and whether the metric matches the product goal.

Common mistakes

  • Reporting a single number with no n and no interval.
  • Tuning prompts on the test set.
  • Treating LLM-judge scores as ground truth.
  • Assuming a held-out split is uncontaminated because exact strings do not match.
