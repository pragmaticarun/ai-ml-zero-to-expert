Block 1: Concept lesson (1h15)

Intuition. Given data and a family of distributions with a knob θ, which θ makes the observed data most probable? That is maximum likelihood. If you flip a coin 200 times and see 141 heads, the bias that best "explains" this is p = 141/200 = 0.705. Any other p would make seeing exactly this data less likely.

Plain-language maths. - Likelihood L(θ) = Πᵢ p(xᵢ | θ), the product of the probabilities of each independent observation. - Products of many small numbers underflow, so take logs: log-likelihood ℓ(θ) = Σᵢ log p(xᵢ | θ). The log is monotonic, so the maximiser is unchanged. - Coin: ℓ(p) = k log p + (n − k) log(1 − p). Setting dℓ/dp = k/p − (n − k)/(1 − p) = 0 gives p̂ = k/n. - Gaussian: ℓ(μ, σ²) = −(n/2)log(2πσ²) − Σ(xᵢ − μ)²/(2σ²). The maximiser has μ̂ = the sample mean and σ̂² = (1/n)Σ(xᵢ − μ̂)², the biased "divide by n" version. - Regression: assume y = wx + b + ε with ε ~ N(0, σ²). Then ℓ(w, b) = const − (1/(2σ²)) Σ(yᵢ − wxᵢ − b)². Maximising the likelihood is the same as minimising the sum of squared errors. MSE is not arbitrary: it is the right cost when the noise is Gaussian. If the noise were Laplace-distributed, MLE would give mean absolute error instead. - Classification preview: for y ∈ {0, 1} with P(y = 1) = p(x), the negative log-likelihood is −[y log p + (1 − y) log(1 − p)]. That is exactly the log-loss (cross-entropy) used for logistic regression on Day 26.

Verified results (code/week-03/day21_mle_project.py): - coin: 141/200 heads, grid MLE 0.705 = closed form 0.705 ✓ - Gaussian: μ̂ = 5.079 and σ̂² = 3.846 (MLE), with the unbiased estimate 3.853 (true values 5 and 4) - regression by gradient ascent on the log-likelihood: w = 2.4975, b = 1.2503, identical to np.polyfit ✓ (true values 2.5 and 1)

Block 2: Worked example (45 min)

Derive the coin MLE fully. ℓ(p) = k ln p + (n − k) ln(1 − p). ℓ′(p) = k/p − (n − k)/(1 − p) = 0, so k(1 − p) = (n − k)p, so k = np, so p̂ = k/n. The second derivative −k/p² − (n − k)/(1 − p)² < 0, so it is a maximum ✓. With n = 10 and k = 7: ℓ(0.7) = 7 ln 0.7 + 3 ln 0.3 = 7(−0.3567) + 3(−1.2040) = −2.497 − 3.612 = −6.109, and ℓ(0.5) = 10 ln 0.5 = −6.931. So 0.7 explains the data better, as expected.

Common mistakes / how to debug

  • Maximising the likelihood directly underflows to 0. Always use log-likelihoods.
  • Sign confusion: maximise ℓ, or equivalently minimise −ℓ (what optimisers do).
  • log(0) = −inf. Clip probabilities to [1e-12, 1 − 1e-12].
